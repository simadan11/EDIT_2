# Дорожная карта LUMEN

## Уже в ядре (1.0)

- [x] Конвейер «Луч» (6 стадий) с живыми событиями (SSE)
- [x] Защитный слой (anti-injection, лимиты, уровни риска)
- [x] Память: 3 слоя, авто-извлечение, relevance-выборка, импорт legacy
- [x] Реестр инструментов + legacy-мост к `actions/*`
- [x] Backends: LHC, Gemini, OpenAI-совместимый + деградация
- [x] Обучающая петля: фидбэк, предпочтения, экспорт корпуса
- [x] Веб-интерфейс «Luminance» + CLI + REST API
- [x] **LUMEN Core (1.1)** — единственный ИИ платформы (без
  внешних API): база знаний (117 фактов), диалоговая анафора,
  календарная математика, текстовая статистика; внешние
  генеративные модули (Gemini/OpenAI) из платформы удалены
- [x] **LUMEN 1.3** — «думает, говорит, учится сам»:
  - видимые «мысли» LUMEN: трасса рассуждений на каждой стадии
    (SSE-событие `thought`, журнал `thoughts.jsonl`, UI-панель);
  - голос в веб-интерфейсе без внешних API: TTS/STT браузера
    (🔊 ответы вслух, 🎤 голосовой ввод, auto-speak);
  - самообучение каждые 60 с (AutoLearner: harvest фактов,
    «фокус», heartbeat-журнал);
  - настольная программа `python -m lumen desktop` (tkinter).

## Ближайшее (1.x)

- **Файлы как данные** — инструменты чтения/анализа документов
  (md, txt, json, csv), суммаризация, извлечение таблиц.
- **Веб-инструмент** — `web.fetch` + `web.search` в ядре (сейчас —
  legacy-адаптер и погода).
- **Мультиагентный план** — намерение `agent_task`: цепочка инструментов
  с промежуточным контролем (пошаговое подтверждение в UI).
- **Push-уведомления** — результаты мониторинга (legacy.background_monitor)
  в web-интерфейс через SSE-канал уведомлений.

## Дальнейшее (2.x)

- **Fine-tuning** — корпус из обучающей петли → дообучение локальной
  модели (Ollama/LM Studio) под стиль LUMEN; бэкенд без переписывания.
- **Мобильный модуль** — face-auth вход (возвращение возможности из
  предшествующей версии в новой архитектуре), голосовой канал из
  телефона, PWA-установщик.
- **Мультипользовательский режим** — профили, пер-юзер память и
  предпочтения, RBAC поверх API.
- **Модельный роутинг** — по мере появления собственных локальных
  модулей (например, дообученной модели): автоматический выбор
  генератора по сложности запроса, по политике — всё локальное,
  без внешних API.
- **Плагин-API для инструментов** — внешние Python-пакеты,
  регистрирующие инструменты без правок ядра.

## Принципы развития

1. Ядро не меняется ради функции — функции приходят инструментами.
2. Каждый новый модуль обязан иметь тесты и честный `unavailable`.
3. Данные пользователя остаются локальными по умолчанию.
4. Бренд — только через `docs/BRANDING.md`.
