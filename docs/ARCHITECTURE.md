# Архитектура LUMEN-1

LUMEN-1 — ядро платформы. Принципиальная разница с предшествующими
версиями: **оркестрация вынесена в ядро**, и ядро **само умеет
отвечать**: единственный генеративный модуль стадии 6 — LUMEN Core,
собственный локальный ИИ (база знаний, диалог, вычисления).
Внешних генеративных моделей в платформе нет — генерация всегда
локальная, без API-ключей и сети.

## Конвейер «Луч»

Каждый запрос проходит шесть стадий (`lumen/kernel/engine.py`):

| # | Стадия | Модуль | Что делает |
|---|---|---|---|
| 1 | **Приём** | `kernel/safety.py` | NFKC-нормализация, лимит длины, контроль управляющих символов, анти-спам (повторы, пунктуационный флуд) |
| 2 | **Защита** | `kernel/safety.py` | Паттерны prompt-injection (RU/EN), запросы-ловушки (деньги, взлом, destructive), уровни риска `safe / caution / blocked` |
| 3 | **Анализ** | `kernel/planner.py` | Детерминированная классификация намерений (19 намерений, RU/EN), извлечение слотов (выражение, город, файл, факт, дата), анафора («а в Киеве?» наследует предыдущий план), план с вызовами инструментов и уверенностью |
| 4 | **Контекст** | `kernel/context.py` | Системный промпт персоны + выученные предпочтения + топ-K семантических фактов (relevance) + история сессии с бюджетом токенов + блок результатов инструментов |
| 5 | **Инструменты** | `kernel/tools.py` | Исполнение плана: таймаут в отдельном потоке, изоляция ошибок, нормализация аргументов по схеме, честная доступность |
| 6 | **Генерация** | `kernel/backends.py` + `kernel/brain.py` | **LUMEN Core** — единственный модуль (собственный ИИ: база знаний, диалог, вычисления); офлайн, без внешних API |
| + | **Запоминание** | `kernel/memory.py` | Сессия (working + episodic JSONL), авто-извлечение фактов, обновление статистики обучения |

Все стадии публикуют события в `EventBus` и в SSE-поток — UI показывает
жизнь конвейера в реальном времени.

### Почему анализ детерминирован

Классификатор намерений — регулярные правила, а не LLM: план должен быть
быстрым (< 1 мс), объяснимым (в UI виден интент и уверенность) и
воспроизводимым. Генерацию выполняет тот же собственный модуль
LUMEN Core (детерминированное рассуждение, база знаний, вычисления) —
внешних LLM в платформе нет.

## Слой памяти

`kernel/memory.py` — три слоя:

```
┌─────────────────────────────────────────────────────────────┐
│ working   — реплики активной сессии (deque + JSONL-журнал)  │
│ episodic  — lumen_data/sessions/<sid>.jsonl (пожизненно)    │
│ semantic  — lumen_data/memory.json: категории identity,     │
│             preferences, projects, relationships, wishes,   │
│             notes (совместимы с legacy-форматом)            │
└─────────────────────────────────────────────────────────────┘
```

- **Relevance-выборка** — токен-оверлеп запроса и фактов + мини-тезаурус
  («имя/имени» → `user_name`, «город» → `city`…).
- **Авто-извлечение** — паттерны `harvest()`: «меня зовут X», «живу в X»,
  «мне нравится X»… попадают в семантический слой без явной команды.
- **Лимиты** — `max_facts` с вытеснением старейших; атомарная запись
  (tmp + rename), потоковая блокировка.
- **Импорт** — `import_legacy()` переносит `memory/long_term.json`
  предшествующей версии в семантический слой (origin: `legacy-import`).

## Реестр инструментов

`kernel/tools.py`:

- `ToolSpec` — имя, заголовок, описание, параметры (тип/обязательность/
  дефолт), таймаут, проверка доступности, источник (`builtin | legacy | user`).
- Исполнение: отдельный поток + `join(timeout)` → кроссплатформенный
  таймаут; любое исключение превращается в `ToolResult(ok=False, error)`.
- `dict`-результат с ключом `ok: False` корректно помечает ошибку.
- **Legacy-мост** (`lumen/tools/adapters.py`) — адаптеры `actions/*`:
  ленивый импорт, binding только принимаемых аргументов, честный
  `unavailable` с причиной, если зависимости не установлены.

### Как добавить инструмент

```python
from lumen.kernel import ToolSpec, ToolParam

def my_handler(what: str = "") -> dict:
    return {"text": f"Сделано: {what}"}

registry.register(ToolSpec(
    name="my.tool", title="Мой инструмент",
    description="Что он делает", handler=my_handler,
    category="general", icon="🧪",
    params=[ToolParam("what", "string", "Что сделать", False, "")],
))
```

UI, API и LUMEN Core подхватят его автоматически (схема читается из реестра).

## LUMEN Core — собственный ИИ (основной генеративный модуль)

`kernel/brain.py` + `lumen/knowledge/` — собственный локальный разум
платформы на чистом Python. Это НЕ «заглушка» и не обёртка над облачной
моделью:

- **База знаний** (`knowledge/base.py`) — 100+ фактов (география, наука,
  математика, IT, история, повседневность, о себе, юмор) с
  офлайн-поиском: стем-толерантное сопоставление запроса по
  вопросам/тегам/ответу, оценка релевантности.
- **Диалоговое состояние** — анафора: короткое продолжение («а в
  Киеве?», «а 5×7?») наследует намерение/слоты предыдущего запроса;
  составные запросы собирают ответы нескольких инструментов.
- **Локальные вычислители** — календарная математика («сколько дней до
  31 декабря?», «через 30 дней»), текстовая статистика (слова/знаки в
  цитате), безопасный калькулятор.
- **Генерация с вариациями** — детерминированная вариативность шаблонов
  по хэшу сообщения (стабильно на одно сообщение, разнообразно между
  разными).
- **Честность** — если запроса нет в ядре, Core прямо говорит, чего
  не хватает, и перечисляет, чем реально может помочь. Внешних
  модулей, на которые «передать» запрос, нет.

## Генеративный модуль (backend)

| Backend | Сеть/ключ | Роль |
|---|---|---|
| **LUMEN Core** (`LumenCoreBackend`, `provider=lumen_core`) | нет / нет | **Единственный** модуль — собственный ИИ: база знаний, диалог, вычисления, инструменты. Платформа всегда отвечает, офлайн |

`HeuristicBackend` — историческое имя LUMEN Core (полностью
совместимо). Любое старое значение `backend.provider` (включая
`gemini`, `openai`) теперь тоже даёт LUMEN Core: внешних модулей в
платформе нет, поле читается для совместимости со старыми
конфигами.

## Обучающая петля

`kernel/learning.py`:

1. **Фидбэк** — `POST /api/feedback` пишет JSONL-запись.
2. **Адаптация** — оценки и заметки конвертируются в «выученные
   предпочтения» (с балансом голосов), которые встраиваются в
   системный промпт каждой генерации.
3. **Корпус** — `export_corpus()` собирает из всех сессий пары
   «запрос → ответ → оценка» → JSONL-датасет для future дообучения
   самого LUMEN Core.
4. **Статистика** — намерения, инструменты, уровень одобрения.

Это честная петля «сигнал → адаптация → генерация» без претензии на
дообучение весов; расширение (новые источники сигнала) — добавлением
обработчиков, ядро не меняется.

## Безопасность

- **Защитный слой** до генератора: blocked-запросы не доходят до
  backends (ответ — стандартная вежливая отсылка).
- **Калькулятор** — AST-оценка только чисел/операторов/белый список
  функций (`sqrt, sin, cos, log, abs, min, max, floor, ceil`);
  имена/импорт/атрибуты отклоняются на уровне парсинга.
- **Поиск файлов** — только внутри корня проекта, тяжёлые каталоги
  пропускаются, жёсткий лимит результатов.
- **HTTP** — лимит тела 256 КБ, структурированные 4xx/5xx, опциональный
  Bearer-токен на весь интерфейс, path-traversal-защита статики,
  CORS не включён (same-origin).
- **Память** — значения фактов обрезаны до 500 знаков, ключи до 80.

## Поток данных (пример)

```
«Вычисли 12 × 8 + 4»
  → intake: safe (731 знаков → 14)
  → guard:  safe
  → plan:   math, conf=0.95, слот expression="12 × 8 + 4", tool=math.calc
  → tools:  math.calc ok (0 мс) → "≈ 100"
  → context: persona(balanced) + facts(0) + history(2) ≈ 340 tokens
  → generate: LUMEN Core → «12 × 8 + 4  ≈ 100.»
  → remember: user+lumen → session, harvest=0, stats.math+=1
  → SSE: 8 событий (start, intake, plan, tool, context, remember, done, result)
```

## Компоненты платформы

```
lumen/
├── __init__.py        # бренд, версия
├── __main__.py        # CLI: serve | chat | tools | status | memory
├── config.py          # LumenConfig (config/lumen.json, миграции)
├── persona.py         # идентичность и системный промпт
├── kernel/            # ЯДРО LUMEN-1
│   ├── engine.py      # LumenEngine — оркестратор «Луч»
│   ├── safety.py      # ThreatGuard (приём + защита)
│   ├── planner.py     # IntentPlanner (намерения, слоты)
│   ├── context.py     # ContextWeaver (промпт-контекст с бюджетом)
│   ├── brain.py       # LUMEN Core — собственный ИИ (единственный)
│   ├── backends.py    # LumenCoreBackend — фабрика (внешних модулей нет)
│   ├── memory.py      # MemoryFabric (3 слоя)
│   ├── tools.py       # ToolRegistry / ToolSpec / ToolResult
│   ├── learning.py    # LearningLoop (фидбэк, предпочтения, корпус)
│   └── events.py      # EventBus (pub/sub)
├── knowledge/         # Встроенная база знаний LUMEN Core (офлайн)
├── tools/             # Встроенные инструменты + legacy-мост
├── io/                # text.py (markdown→speech), voice.py (TTS/STT)
├── api/               # server.py — REST + SSE (stdlib)
└── web/               # Индекс, CSS-система «Luminance», app.js
```
